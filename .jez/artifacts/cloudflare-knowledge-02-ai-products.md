## 1. Workers AI

Serverless GPU inference on the Cloudflare network. The flagship of Cloudflare's AI offering — 50+ open-source models accessed through a single binding, with usage measured in "Neurons" against a daily free allowance.

### 1.1 Binding (exact wrangler.jsonc)

```jsonc
"ai": { "binding": "AI" }
```

That's literally it — no model ID, no region, no API key. The binding is account-scoped: it inherits your Cloudflare account's identity from `wrangler.toml`/dashboard.

For Pages Functions, the binding is configured via the dashboard, not the wrangler file.

TypeScript types are autogenerated by `wrangler types`:

```bash
npx wrangler types
# generates worker-configuration.d.ts with `AI: Ai` on the Env interface
```

### 1.2 Calling the binding — text generation

```typescript
// Non-streaming
const response = await env.AI.run('@cf/meta/llama-3.3-70b-instruct-fp8-fast', {
  messages: [
    { role: 'system', content: 'You are a helpful assistant.' },
    { role: 'user',   content: 'What is Cloudflare Workers AI?' },
  ],
  max_tokens: 1024,
  temperature: 0.7,
})
// response: { response: string, usage: { prompt_tokens, completion_tokens, total_tokens } }
```

```typescript
// Streaming (Server-Sent Events)
const stream = await env.AI.run('@cf/meta/llama-3.3-70b-instruct-fp8-fast', {
  messages: [{ role: 'user', content: 'Write a haiku about Cloudflare' }],
  stream: true,
}) as ReadableStream
return new Response(stream, {
  headers: { 'Content-Type': 'text/event-stream' },
})
```

### 1.3 Calling the binding — embeddings

```typescript
const embeddings = await env.AI.run('@cf/baai/bge-base-en-v1.5', {
  text: ['Some text to embed', 'Another piece of text'],
})
// embeddings.data is an array of 768-dim Float32 vectors
// IMPORTANT: extract via embeddings.data[0], not the response object itself,
// when feeding to env.VECTOR_INDEX.query()
```

### 1.5 Calling the binding — image generation (FLUX 2 — multipart API)

FLUX 2 uses multipart FormData, not JSON. Sending JSON to FLUX 2 fails. (See `rules/workers-ai-gotchas.md`.)

```typescript
const form = new FormData()

form.append('width', '1920')
form.append('height', '1080')
form.append('guidance', '3.5')   // 1-20, optional
form.append('steps', '20')        // FLUX 2 Dev only; Klein is fixed at 4

const formResponse = new Response(form)
const result = await env.AI.run('@cf/black-forest-labs/flux-2-klein-9b', {
  multipart: {
    body: formResponse.body!,
    contentType: formResponse.headers.get('content-type')!,
  },
})
const img = (result as Record<string, unknown>).image as string  // base64
const imageData = new Uint8Array(atob(img).split('').map(c => c.charCodeAt(0)))
```

### 1.9 OpenAI-compatible endpoints

Workers AI exposes OpenAI-compatible REST endpoints at `https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/v1/chat/completions` and `/v1/embeddings`. Useful for SDKs that don't speak Cloudflare's native shape.

The Workers binding does NOT use these endpoints — it goes direct over an internal RPC fabric.

### 1.10 Pricing model — Neurons

Workers AI bills in **Neurons** — abstract GPU-compute units at **$0.011 per 1,000 Neurons**.

- **Free tier:** 10,000 Neurons/day on Free AND Paid plans, resets 00:00 UTC.
- **Free plan:** above 10K/day, requests are rate-limited (not charged).
- **Paid plan:** above 10K/day, charges accrue at the per-million-token rates.

Per-million-token pricing for popular text models:

| Model | Input $/M | Output $/M |
|---|---:|---:|
| `@cf/meta/llama-3.2-1b-instruct` | $0.027 | $0.201 |
| `@cf/meta/llama-3.2-3b-instruct` | ~$0.05 | ~$0.30 |
| `@cf/meta/llama-3.3-70b-instruct-fp8-fast` | $0.293 | $2.253 |
| `@cf/meta/llama-4-scout-17b-16e-instruct` | $0.27 | $0.85 |
| `@cf/mistralai/mistral-7b-instruct` | $0.110 | $0.190 |
| `@cf/qwen/qwen3-30b-a3b-fp8` | $0.051 | $0.335 |
| `@cf/openai/gpt-oss-20b` | (verify via dashboard) | — |
| `@cf/openai/gpt-oss-120b` | (verify via dashboard) | — |

Embeddings: $0.012–$0.204 per million input tokens depending on model. `@cf/baai/bge-base-en-v1.5` is $0.067/M.

Image generation:
- **FLUX 1 schnell:** ~$0.000053 per 512×512 tile
- **FLUX 2 Klein 9B:** $0.015 per first megapixel, then $0.002 per additional MP

| Limit | Value |
|---|---|

### 1.12 LoRA / fine-tuning (BYOL — Bring Your Own LoRA)

In **open beta, free to use** as of mid-2026.

**Constraints:**
- Adapter rank ≤ 8 (up to 32 for larger ones)
- File size ≤ 300 MB
- Exact filenames: `adapter_config.json` + `adapter_model.safetensors`
- 100 adapters per account
- `adapter_config.json` must include `"model_type"` set to `mistral`, `gemma`, or `llama`

**Supported base models (non-quantized):** check the docs for the current list — `@cf/mistralai/mistral-7b-instruct-v0.2-lora`, `@cf/meta/llama-3.1-8b-instruct`, and similar.

**Upload:**
```bash
npx wrangler ai finetune create <model_name> <finetune_name> <folder_path>
```

**Inference:**
```typescript
await env.AI.run('@cf/mistralai/mistral-7b-instruct-v0.2-lora', {
  messages: [{ role: 'user', content: 'Hello' }],
  raw: true,
  lora: 'finetune_id_or_name',
})
```

**Office Town relevance:** v2 at earliest. Useful if a deployment wants a wiki-content-specific tone model, but smart-default Llama is generally fine.

### 1.13 Function / tool calling

Models marked with the `function-calling` capability support OpenAI-style tool definitions. Llama 4 Scout, Nemotron-3 120B, Qwen3, and Mistral Small 3.1 all support it.

Two paths:

1. **Native** — pass `tools` parameter, model returns `tool_calls` array, you execute and loop.
2. **Embedded (`@cloudflare/ai-utils`)** — abstracts the loop. Reduces ~77 lines to ~31.

Bake-off finding from `rules/workers-ai-gotchas.md`: for nested-enum Zod schemas via AI SDK v6 + `workers-ai-provider`, Nemotron-3 120B and Qwen3-30B win; gpt-oss-120b fails. For flat JSON-as-text plans, gpt-oss-20b wins. **Always re-test for the actual workload.**

### 1.14 Comparison to OpenAI/Anthropic via Wrangler

You don't need a "Cloudflare" wrapper to call OpenAI or Anthropic from a Worker — just `fetch()` with the API key as a secret. But for shared concerns (caching, fallback, rate limiting), route through AI Gateway (§ 3).

| Aspect | Workers AI | OpenAI/Anthropic via fetch |
|---|---|---|
| Auth | None (account-scoped binding) | API key as secret |
| Cost | Pay per Neuron, 10K/day free | Pay per token, no free tier |
| Latency | Co-located with Worker — sub-100ms cold | 100-500ms typical |
| Model choice | 50+ open-source | GPT-5, Claude Opus 4.7, etc. |
| Streaming | Yes, SSE | Yes, SSE |
| Tool use | Some models | All flagship models |
| Multi-region | Automatic | Single region |

**Office Town stance:** default to Workers AI for embeddings, image generation, TTS/STT, simple text generation. Use Anthropic Sonnet/Opus via fetch (or via the user's choice — Goose handles provider selection) for high-stakes reasoning. Use AI Gateway as a fallback router when both are available.

## 2. The toMarkdown utility

A free document-conversion utility on the AI binding — invaluable for ingesting user-uploaded files into the wiki.

### 2.1 Supported formats

| Format | Cost | Notes |
|---|---|---|
| PDF | Free | Text extraction; complex layouts may lose structure |
| DOCX | Free | Word documents — paragraphs, headings, tables |
| XLSX | Free | Excel — converts sheets to Markdown tables |
| PPTX | Free | PowerPoint — slide titles + bullets |
| HTML | Free | Strips chrome, keeps structure |
| MD | Free | Passes through |
| Images (PNG/JPG/WebP) | **Charged** — uses Workers AI vision under the hood | Object detection + summary |
| Audio (MP3/WAV/M4A) | **Charged** — uses Whisper | Transcription as Markdown |

### 2.2 Calling the binding

```typescript
const results = await env.AI.toMarkdown([
  {
    name: 'document.pdf',
    blob: pdfBlob,             // a Blob or File
  },
  {
    name: 'spreadsheet.xlsx',
    blob: xlsxBlob,
  },
])
// results: Array<{ name, mimeType, format, tokens, data: string /* the Markdown */ }>

for (const r of results) {
  console.log(`${r.name} (${r.tokens} tokens):\n${r.data}`)
}
```

Single-file shape (also accepted):
```typescript
const result = await env.AI.toMarkdown({
  name: 'invoice.pdf',
  blob: pdfBlob,
})
```

### 2.3 REST API equivalent

```bash
curl https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/tomarkdown \
  -H "Authorization: Bearer {API_TOKEN}" \
  -F "files=@document.pdf"
```

### 2.4 Limits

- **Max file size:** documented limits vary — assume ≤ 10 MB to be safe per file, verify with the actual Cloudflare docs.
- **Batch size:** small batches (< 10 files) recommended; larger uses more memory.
- **Throughput:** counts against the AI quota for any model-invoking conversions (images, audio).

### 2.5 Office Town relevance — v1.0 critical

This is one of the biggest single-binding wins for Office Town. Users uploading PDFs / DOCXs to the wiki should hit `env.AI.toMarkdown()` automatically on ingest, with the extracted Markdown stored alongside the original in R2 and indexed into Vectorize. No external service, no parser to maintain.

**Build pattern:**
```typescript
// On R2 upload via Queues consumer
const file = await env.FILES.get(key)
const blob = await file!.blob()
const [{ data: markdown }] = await env.AI.toMarkdown([{ name: key, blob }])

// Store the .md alongside the original
await env.WIKI.put(`${key}.md`, markdown)

// Chunk + embed + insert to Vectorize
const chunks = chunkText(markdown, { size: 512, overlap: 64 })
const { data: vectors } = await env.AI.run('@cf/baai/bge-base-en-v1.5', { text: chunks })
await env.VECTOR_INDEX.upsert(vectors.map((v, i) => ({
  id: `${key}::${i}`,
  values: v,
  metadata: { sourceKey: key, chunkIndex: i, text: chunks[i] },
})))
```

## 3. AI Gateway

A proxy that sits in front of any AI provider (Workers AI, OpenAI, Anthropic, Google, Replicate, etc.) and adds caching, rate limiting, fallback, retry, observability, and DLP.

### 3.1 What it does

- **Caching** — identical prompts return cached responses (huge cost win for embedding-style workloads).
- **Rate limiting** — per-key, per-model, per-endpoint quotas.
- **Fallback** — define a chain "try Anthropic; on 429/500 try OpenAI; on 429/500 try Workers AI".
- **Retry** — exponential backoff on transient errors.
- **Observability** — dashboard view of requests, tokens, costs, errors.
- **Logs** — full request/response logs (with optional DLP redaction).
- **DLP** — Data Loss Prevention scans prompts/responses for sensitive content.
- **Costs tracker** — rolls up spend across providers in one view.
- **Realtime metrics** — error rate, latency, p50/p95/p99.

### 3.2 Binding (Workers AI through Gateway)

Add `gateway` parameter to any `env.AI.run()` call:

```typescript
const response = await env.AI.run('@cf/meta/llama-3.3-70b-instruct-fp8-fast', {
  messages: [...],
}, {
  gateway: {
    id: 'my-gateway-id',
    skipCache: false,
    cacheTtl: 3600,
    metadata: { user: 'jez', tag: 'wiki-summarize' },
  },
})
```

No separate `wrangler.jsonc` binding needed — the gateway is identified by ID against your Cloudflare account.

### 3.3 Routing other providers through Gateway

OpenAI example:

```typescript
const response = await fetch(
  'https://gateway.ai.cloudflare.com/v1/{ACCOUNT_ID}/{GATEWAY_ID}/openai/chat/completions',
  {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${env.OPENAI_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: 'gpt-5',
      messages: [{ role: 'user', content: 'Hello' }],
    }),
  }
)
```

Anthropic example:

```typescript
const response = await fetch(
  'https://gateway.ai.cloudflare.com/v1/{ACCOUNT_ID}/{GATEWAY_ID}/anthropic/v1/messages',
  {
    method: 'POST',
    headers: {
      'x-api-key': env.ANTHROPIC_API_KEY,
      'anthropic-version': '2023-06-01',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: 'claude-opus-4-7',
      max_tokens: 1024,
      messages: [{ role: 'user', content: 'Hello' }],
    }),
  }
)
```

### 3.4 Streaming caveat (CRITICAL — per `rules/cloudflare-workers.md`)

**Do NOT route streaming responses through AI Gateway.** Known issues:

- Multibyte character corruption (emojis, non-ASCII chars come back broken)
- DLP buffering kills time-to-first-token
- Streaming × caching interaction is undocumented

| If Claude suggests... | Use instead... |
|---|---|
| Route Claude API streaming through AI Gateway | Call Anthropic API directly with `fetch()` |
| AI Gateway for cost tracking on streaming | Log usage server-side in D1 |
| AI Gateway for caching streaming responses | Cache after stream completes; use Anthropic's native prompt caching |

**OK for:** non-streaming batch processing, background extraction, embedding endpoints, scheduled jobs. **Test before deploying** — the streaming bugs sometimes surface only with specific models.

### 3.5 Pricing

AI Gateway itself is **free** (in beta as of 2026). You pay only for the underlying provider calls. Cached hits don't incur provider charges.

### 3.6 Office Town relevance — v1.1

Worth adding once Office Town fleets call multiple providers — e.g. one user wires their personal OpenAI key, another wires Anthropic, the platform wires Workers AI as fallback. AI Gateway gives consistent observability across all of them.

For pure Workers-AI-only setups (the v1.0 default), Gateway adds caching + logs without much downside. Worth turning on day-1 for the cache hit alone on the embedding pipeline.

## 4. AI Search (managed RAG)

Released **April 2026** — Cloudflare's managed retrieval-augmented-generation service. Previously known as **AutoRAG**, now renamed. Connects to a data source (R2 bucket, website crawl, or direct file upload), handles chunking + embedding + indexing automatically, and exposes a search-or-generate API.

### 4.1 What it is

A drop-in managed RAG that gives you:

1. **Continuous indexing** — files dropped into R2 (or website pages crawled) are automatically chunked, embedded, and made searchable.
2. **Hybrid search** — vector + keyword fused.
3. **Metadata filtering** — pass user-defined filters at query time.
4. **Generation** — built-in `/chat/completions` endpoint that runs RAG + generation in one call.
5. **MCP endpoint** — agents can plug AI Search into their tool registry as an MCP server.
6. **Embed component** — drop-in search widget for any site.

### 4.2 Binding (instance binding)

```jsonc
// wrangler.jsonc
"ai_search": [
  {
    "binding": "MY_SEARCH",
    "instance_name": "office-town-wiki-search",
    "remote": true  // optional — proxy to deployed instance during local dev
  }
]
```

Namespace binding (when you need runtime instance selection):

```jsonc
"ai_search_namespaces": [
  { "binding": "SEARCH_NS", "namespace_name": "office-town" }
]
```

> The older `env.AI.autorag()` shape is **deprecated** — use the binding above.

### 4.3 Calling the binding — search only

```typescript
const result = await env.MY_SEARCH.search({
  query: 'How does Office Town handle file uploads?',
  max_num_results: 10,
  rewrite_query: true,
  ranking_options: { score_threshold: 0.5 },
  // filters: { ... } — metadata filters
})
// result.data: Array<{ file_id, filename, score, attributes, content: [{ text, type }] }>
```

### 4.4 Calling the binding — search + generation

```typescript
const result = await env.MY_SEARCH.chatCompletions({
  messages: [
    { role: 'user', content: 'How does Office Town handle file uploads?' },
  ],
  stream: false,
  max_num_results: 5,
  // model: '@cf/meta/llama-3.3-70b-instruct-fp8-fast',  // override generation model
})
// result.response, result.data, result.search_query (rewritten)
```

Streaming variant:

```typescript
const stream = await env.MY_SEARCH.chatCompletions({
  messages: [{ role: 'user', content: '...' }],
  stream: true,
})
return new Response(stream, { headers: { 'Content-Type': 'text/event-stream' } })
```

### 4.5 REST API

```bash
# Search only
curl https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai-search/instances/{INSTANCE_NAME}/search \
  -H "Authorization: Bearer {AI_SEARCH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "office town file uploads",
    "max_num_results": 10
  }'

# Search + generation (OpenAI-compatible messages format)
curl https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai-search/instances/{INSTANCE_NAME}/chat/completions \
  -H "Authorization: Bearer {AI_SEARCH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{ "role": "user", "content": "..." }],
    "stream": false
  }'
```

Permissions required: **AI Search:Edit** + **AI Search:Run**.

### 4.6 How chunking works

- **Strategy:** **recursive chunking** — splits at natural boundaries (paragraphs → sentences) then sub-splits if too large.
- **Chunk size:** configurable in tokens, range varies by embedding model.
- **Chunk overlap:** 0–30% configurable.
- **Smaller chunks** = more vectors (cost) but tighter retrieval. **Larger chunks** = fewer vectors but more context per hit.

### 4.7 Models used internally

AI Search runs a multi-stage pipeline. Each stage has a configurable model (or "Smart Default" — Cloudflare picks and auto-updates):

| Stage | Configurable | Notes |
|---|---|---|
| Image-to-markdown (ingestion) | Yes | Vision model converts images to text |
| Embedding | **Fixed at instance creation** | Default smart pick; once set, can't change |
| Query rewriting | Yes, anytime | Reformulates user query for better retrieval |
| Reranking | Yes, anytime | bge-reranker or similar |
| Generation | Yes, anytime AND per-request | The LLM that writes the answer |

**Provider support:** native Workers AI; OpenAI/Anthropic via AI Gateway after wiring credentials into the gateway.

### 4.8 Data sources

Fixed at creation time:

1. **Direct upload** — drop files into AI Search's managed storage.
2. **R2 bucket** — point at any R2 bucket; new files indexed automatically.
3. **Website crawl** — give AI Search a URL on a domain you own (DNS-verified); it crawls and indexes.

### 4.9 Configurable post-creation

- Path filters (include/exclude patterns)
- Sync schedule (on demand vs continuous)
- Search mode (vector / keyword / hybrid)
- Custom metadata fields
- Result filtering and boosting
- Reranking on/off
- Query rewriting on/off
- Similarity caching (free cache hit when query is near-duplicate of a recent query)
- Public endpoints (expose search to the open web)
- Embeddable UI components

### 4.10 Pricing

**Free in beta** (instances created after 2026-04-16 include managed storage + vector indexing + web crawling at no charge through beta). Production pricing TBA but expected to be a flat per-MB-stored + per-query model.

### 4.11 Office Town relevance — v1.1 critical decision point

AI Search is the **single biggest architectural question for Office Town's future**.

**Today (v1.0):** Office Town builds RAG manually — chunk in code, embed via `env.AI.run('@cf/baai/bge-base-en-v1.5', ...)`, store in `env.VECTOR_INDEX` with metadata pointing at R2 source. Custom retrieval, custom reranking, custom generation prompt.

**Tomorrow (v1.1 or v2):** If AI Search proves out in beta:
- Replace the entire chunk/embed/index pipeline with a `ai_search` binding pointing at the `WIKI` R2 bucket.
- Delete the Queue consumer code that handles ingestion.
- Replace the search endpoint with `env.MY_SEARCH.search()`.
- Optionally replace generation with `env.MY_SEARCH.chatCompletions()` (or keep our own for finer control).

**Why we don't switch today:**
1. Beta — terms can change, models can move; not ideal for a public release.
2. Embedding model is fixed at instance creation — locks us in.
3. Less control over chunking edge cases (which we'd want for code blocks, frontmatter, etc.).
4. Less visibility into what's indexed vs not.

**Why we might switch later:**
1. Removes ~300 lines of pipeline code.
2. Continuous indexing is non-trivial to maintain.
3. AI Search's hybrid search + similarity cache is hard to beat.
4. MCP endpoint comes free.

## 5. Cloudflare Agents SDK

A TypeScript framework for building **stateful AI agents** as Durable Objects. Released as a first-class product in 2025-2026. Each Agent is its own DO instance with embedded SQLite, WebSocket connections, scheduling, and an AI model lifecycle.

### 5.1 What it is

Per the docs: agents that "remember conversations, act on schedules, call tools, coordinate with other agents, and stay connected to users in real-time."

Architecturally:
- **One Agent class = one Durable Object class**, with the SDK adding decorators, lifecycle hooks, and helpers.
- **Each agent instance is identified by a name** (e.g. `user-jez`, `room-general`, `session-abc123`).
- **State persists** in the DO's SQLite + an in-memory cache that auto-saves and syncs to clients.
- **Tasks can be scheduled** for later via `this.schedule()` — survives restarts and hibernation.
- **WebSockets are first-class** — `onConnect`, `onMessage`, `broadcast`.

### 5.2 Install

```bash
npx create-cloudflare@latest --template cloudflare/agents-starter
cd agents-starter && npm install
npm run dev
```

Or add to existing project:

```bash
npm install agents
```

### 5.3 Required wrangler.jsonc

```jsonc
{
  "compatibility_flags": ["nodejs_compat"],   // REQUIRED for the SDK
  "durable_objects": {
    "bindings": [
      { "name": "MyAgent", "class_name": "MyAgent" }
    ]
  },
  "migrations": [
    { "tag": "v1", "new_sqlite_classes": ["MyAgent"] }
  ]
}
```

**Critical:** `new_sqlite_classes` (NOT `new_classes`) — agents require the SQLite storage backend for `this.sql` and `this.state` to work. Migration tags are sequential strings (`v1`, `v2`, ...) — never modify existing ones; add new ones.

### 5.4 Defining an Agent

```typescript
import { Agent } from 'agents'

interface Env {
  MyAgent: DurableObjectNamespace<MyAgent>
  AI: Ai
}

interface State {
  messageCount: number
  lastActive: string
}

export class MyAgent extends Agent<Env, State> {
  initialState: State = { messageCount: 0, lastActive: new Date().toISOString() }

  async onStart() {
    // Runs once when the agent boots or wakes from hibernation
    this.sql`CREATE TABLE IF NOT EXISTS notes (
      id TEXT PRIMARY KEY,
      text TEXT NOT NULL,
      created_at TEXT NOT NULL DEFAULT (datetime('now'))
    )`
  }

  async onRequest(request: Request): Promise<Response> {
    // Standard HTTP handler
    const url = new URL(request.url)
    if (url.pathname === '/note') {
      const { text } = await request.json<{ text: string }>()
      const id = crypto.randomUUID()
      this.sql`INSERT INTO notes (id, text) VALUES (${id}, ${text})`
      this.setState({ ...this.state, messageCount: this.state.messageCount + 1 })
      return Response.json({ id })
    }
    return new Response('Not found', { status: 404 })
  }

  async onConnect(connection: Connection, ctx: ConnectionContext) {
    // New WebSocket
    connection.send(JSON.stringify({ type: 'welcome', state: this.state }))
  }

  async onMessage(connection: Connection, message: string | ArrayBuffer) {
    const data = JSON.parse(message as string)
    if (data.type === 'note') {
      const id = crypto.randomUUID()
      this.sql`INSERT INTO notes (id, text) VALUES (${id}, ${data.text})`
      this.broadcast(JSON.stringify({ type: 'note-added', id, text: data.text }))
    }
  }

  async onClose(connection: Connection, code: number, reason: string, wasClean: boolean) {
    // cleanup
  }
}

// Worker entry — route requests to the agent
import { routeAgentRequest } from 'agents'

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    return (await routeAgentRequest(request, env)) || new Response('Not found', { status: 404 })
  },
}
```

### 5.5 State management

| API | Persistence | Sync to clients | Use for |
|---|---|---|---|
| `this.state` / `this.setState()` | SQLite-backed | **Auto-broadcast to WebSocket clients** | UI state, counters, current session |
| `this.sql` | SQLite | Manual (broadcast yourself if needed) | History, large collections, queryable records |
| In-memory class fields | **Lost on hibernation** | No | Caches you're OK to lose |

```typescript
// State (synced)
this.setState({ ...this.state, messageCount: this.state.messageCount + 1 })

// SQL (not synced)
this.sql<{ id: string, text: string }>`
  SELECT id, text FROM notes WHERE id = ${id}
`

// Validation hook
async validateStateChange(next: State, prev: State): Promise<boolean> {
  return next.messageCount >= prev.messageCount  // monotonic
}

// React hook
async onStateChanged(state: State, source: 'server' | Connection) {
  if (source === 'server') return  // prevent infinite loops
  // do side-effect for client-pushed changes
}
```

### 5.6 Scheduling tasks

```typescript
// Delayed
await this.schedule(30, 'sendReminder', { message: 'Hi' })
// at 30s, calls this.sendReminder({ message: 'Hi' })

// Specific time
await this.schedule(new Date('2026-06-01T09:00:00Z'), 'sendReminder', { message: 'Report due' })

// Cron
await this.schedule('0 8 * * *', 'dailyDigest', { userId: '123' })

// Fixed interval (sub-minute precision)
await this.scheduleEvery(30, 'poll', { source: 'api' })

// Manage
const job = await this.getScheduleById(scheduleId)
const upcoming = await this.listSchedules({
  type: 'cron',
  timeRange: { start: new Date(), end: futureDate },
})
await this.cancelSchedule(scheduleId)
```

Tasks survive hibernation and agent restarts (stored in SQLite). Cron jobs are idempotent — calling `this.schedule('0 8 * * *', ...)` multiple times with the same handler won't create duplicates.

### 5.7 Browser browsing

The Agents SDK exposes two CDP-driven tools for headless browsing:

- **`browser_search`** — query the Chrome DevTools Protocol spec to discover commands.
- **`browser_execute`** — run CDP commands against a live browser session.

Each `browser_execute` call opens a **fresh browser session** — no cookies, no auth, no state preserved across calls. Multi-step workflows must complete inside one code block. Responses are truncated to ~6,000 tokens.

Setup: requires the `@cloudflare/codemode` package + Browser Run binding + Worker Loader binding:

```jsonc
"browser": { "binding": "BROWSER" },
"unsafe": { "bindings": [{ "name": "LOADER", "type": "worker_loader" }] }
```

For multi-step workflows or sessions with auth, drop down to `@cloudflare/puppeteer` directly (see § 7).

Streaming via WebSocket (the recommended pattern):

```typescript
async onMessage(connection: Connection, message: string) {
  const { prompt } = JSON.parse(message)
  const stream = await this.env.AI.run('@cf/meta/llama-3.3-70b-instruct-fp8-fast', {
    messages: [{ role: 'user', content: prompt }],
    stream: true,
  }) as ReadableStream

  const reader = stream.getReader()
  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    connection.send(value)  // forward SSE chunks to client
  }
}
```

If the client disconnects mid-stream, the agent **keeps running** and can resume the conversation when the client reconnects.

### 5.9 Calling agents from a Worker

### 5.11 Running workflows from an agent

class MyWorkflow extends AgentWorkflow<Env, MyAgent> {

### 5.13 Hibernation behaviour

Agents hibernate when idle (configurable threshold). On hibernation:
- **Preserved:** state, SQL data, connection metadata, scheduled tasks.
- **Lost:** in-memory variables, timers, local caches.

`onStart()` runs again when the agent wakes. Use `this.keepAlive()` to prevent hibernation during long operations:

```typescript
const dispose = await this.keepAlive()
try {
  const result = await longRunningTask()
} finally {
  dispose()
}
```

`AIChatAgent` handles this automatically for streaming responses.

### 5.14 Comparison: Agents SDK vs vanilla Workers + MCP

| Aspect | Agents SDK | Vanilla Workers + MCP server |
|---|---|---|
| **State** | Per-instance SQLite + auto-sync | D1 shared + manual sync |
| **Connections** | WebSockets first-class, hibernation-safe | Manual WS handling |
| **Scheduling** | `this.schedule()` built-in | Cron triggers or Queues |
| **Lifecycle** | onConnect/onMessage/onStart hooks | DIY |
| **Multi-tenant isolation** | One DO per user/room | Shared Worker + DB filtering |
| **Latency** | Sub-50ms within a region | Sub-50ms globally |
| **Cost** | DO requests + storage | Worker requests + D1 reads |
| **Best for** | Long-running, stateful, real-time | Stateless, request-response |

### 5.15 Office Town relevance — v1.1 evaluate, v2 likely adopt

**Today (v1.0):** Office Town is a single Worker + bindings + MCP server. Wiki state lives in D1 and R2; the MCP tools are stateless functions. No per-user agents.

**Tomorrow (v1.1 or v2):** Adopt the Agents SDK when Office Town starts hosting **per-user assistant agents** — e.g. each Goose user gets an `office-town/user-jez` agent that:
- Remembers their wiki preferences (which spaces matter, which tags are starred).
- Watches for inbox events on `office-town/inbox/<user>` and processes them.
- Schedules nightly summaries (cron-style).
- Holds an open WebSocket to the user's web UI for live updates.

Until then, the SDK is overkill — D1 + Queues do the same job with less complexity.

**Migration path:** the Agents SDK is additive — you can introduce one Agent class alongside the existing Worker without rewriting anything. Start small (e.g. one agent for nightly summaries) and expand.

## 6. Vectorize (AI focus)

Cloudflare's distributed vector database. Covered structurally in the storage knowledge doc; this section focuses on **AI integration patterns**.

### 6.1 Binding

```jsonc
"vectorize": [
  { "binding": "VECTOR_INDEX", "index_name": "office-town-vec" }
]
```

### 6.2 Index creation (one-time)

```bash
# Office Town uses bge-base-en-v1.5 → 768 dimensions, cosine metric
npx wrangler vectorize create office-town-vec \
  --dimensions=768 \
  --metric=cosine
```

Supported dimensions: 32–1536. Supported metrics: `cosine`, `euclidean`, `dot-product`.

### 6.3 Metadata index ordering — CRITICAL (per `rules/cloudflare-storage.md`)

Vectorize metadata indexes must be created **BEFORE any vectors are inserted**. Vectors inserted before metadata index creation are NOT retroactively indexed — queries with metadata filters return 0 results, with no error.

**Correct order:**

```bash
# 1. Create index
npx wrangler vectorize create office-town-vec --dimensions=768 --metric=cosine

# 2. Create metadata indexes BEFORE inserting any vectors
npx wrangler vectorize create-metadata-index office-town-vec --property-name=sourceKey --type=string
npx wrangler vectorize create-metadata-index office-town-vec --property-name=spaceId --type=string
npx wrangler vectorize create-metadata-index office-town-vec --property-name=updatedAt --type=number

# 3. NOW insert vectors — they'll be filterable
```

**Fix for existing index that was populated before metadata indexes were added:** delete + recreate the index, create metadata indexes, then re-insert all vectors.

### 6.4 Embedding pipeline pattern (Workers AI)

```typescript
// On Queue consumer — process a batch of newly-uploaded files
export default {
  async queue(batch: MessageBatch<{ key: string }>, env: Env) {
    for (const msg of batch.messages) {
      const file = await env.WIKI.get(msg.body.key)
      if (!file) continue
      const text = await file.text()
      const chunks = chunkText(text, { size: 512, overlap: 64 })

      // Embed in batches of ~50 (Workers AI handles this fine)
      const { data: vectors } = await env.AI.run('@cf/baai/bge-base-en-v1.5', {
        text: chunks,
      }) as { data: number[][] }

      await env.VECTOR_INDEX.upsert(vectors.map((v, i) => ({
        id: `${msg.body.key}::${i}`,
        values: v,
        metadata: {
          sourceKey: msg.body.key,
          chunkIndex: i,
          text: chunks[i].slice(0, 2000),  // for citation rendering
        },
      })))

      msg.ack()
    }
  },
}
```

### 6.5 Query pattern

### 6.6 Hybrid search — RRF fusion

Pure vector search misses keyword matches. Pure FTS misses semantic relatives. Reciprocal Rank Fusion (RRF) combines both.

```typescript
async function hybridSearch(db: D1Database, vec: VectorizeIndex, ai: Ai, query: string) {
  // Vector results
  const { data } = await ai.run('@cf/baai/bge-base-en-v1.5', { text: [query] }) as { data: number[][] }
  const vectorMatches = await vec.query(data[0], { topK: 20, returnMetadata: 'all' })

  // FTS results (D1 FTS5 virtual table)
  const ftsResults = await db.prepare(
    `SELECT id, rank FROM docs_fts WHERE docs_fts MATCH ?1 ORDER BY rank LIMIT 20`
  ).bind(query).all<{ id: string, rank: number }>()

  // Reciprocal Rank Fusion
  const scores = new Map<string, number>()
  const k = 60
  vectorMatches.matches.forEach((m, idx) => {
    scores.set(m.id, (scores.get(m.id) ?? 0) + 1 / (k + idx + 1))
  })
  ftsResults.results.forEach((r, idx) => {
    scores.set(r.id, (scores.get(r.id) ?? 0) + 1 / (k + idx + 1))
  })

  return [...scores.entries()]
    .sort((a, b) => b[1] - a[1])
    .slice(0, 10)
    .map(([id, score]) => ({ id, score }))
}
```

`k = 60` is the standard RRF smoothing constant — small enough that top-rank items dominate, large enough that the long tail still contributes.

### 6.7 Bring-your-own-vectors vs Workers AI embeddings

| Source | Pros | Cons |
|---|---|---|
| **`@cf/baai/bge-base-en-v1.5`** | Co-located, sub-50ms latency, $0.067/M tokens, 768-dim, batch-friendly | Quality is "good" not "best"; English-centric |
| **`@cf/baai/bge-m3`** | Multilingual, longer input (8192 tokens), 1024-dim | Slower, more expensive |
| **`@cf/google/embeddinggemma-300m`** | Newer, smaller dimensions | Less benchmarked |
| **OpenAI text-embedding-3-large** | Best quality, 3072-dim | External API call, ~200ms, $0.13/M tokens |
| **Cohere embed-v3** | Excellent reranking | External call, separate billing |

**Office Town stance:** stay on `bge-base-en-v1.5` — 768 dims fits our index, the quality is sufficient for wiki search, and the latency win matters when the embed call sits in a Queue consumer running 20× / minute.

### 6.8 Pricing & limits

| Tier | Queried dimensions/mo | Stored dimensions | Above tier |
|---|---|---|---|
| Free plan | 30M | 5M | (rate-limited) |
| Workers Paid | 50M included | 10M included | $0.01/M queried, $0.05/100M stored |

Per-vector cost is `dimensions × per-vector price`. For 768-dim vectors:
- Storage: ~$0.000038 per stored vector / month
- Query: ~$0.0000077 per query

**Practical scale:** 50K vectors × 200K queries / month at 768-dim ≈ **$1.94 / month**.

- Max 200K vectors per batch insert job
- Max 5,000 vectors per NDJSON file in CLI uploads

Three products under the Realtime umbrella:
1. **RealtimeKit** — high-level SDK with prebuilt UI for video/voice rooms.
2. **Realtime SFU** — low-level WebRTC SFU for custom routing.
3. **TURN service** — managed relay for NAT traversal (free with SFU).

### 10.1 RealtimeKit

Per-minute billing. Includes UI components. Use when you want a Zoom-clone in your app without WebRTC expertise.

### 10.2 Realtime SFU

```bash
# 1,000 GB egress free/month, then $0.05/GB
```

WebRTC SFU on Cloudflare's network. Combine with:
- **Pipecat** — orchestration framework for voice agents (STT → LLM → TTS).
- **smart-turn-v2** — Cloudflare's turn detection model (decides when the user has finished speaking).

### 10.3 Voice agent pipeline (Pipecat)

```
[User mic] → WebRTC → Realtime SFU → Worker
                                         ↓
                                     Pipecat
                                         ↓
        ┌────────────────────────────────┴──────────────────────────┐
        ↓                                                              ↓
    [STT: Nova-3 / Whisper]                                     [smart-turn-v2]
        ↓                                                              ↑
    [LLM: Llama 4 / GPT / Claude]  ← context, tools, RAG ─────────────┘
        ↓
    [TTS: Aura-2 / MeloTTS / ElevenLabs]
        ↓
[User speaker] ← WebRTC ← Realtime SFU ← Worker
```

Pipecat handles the orchestration — interruptions, barge-in, partial transcripts, turn detection. Cloudflare's contribution is the SFU + smart-turn-v2 + the model bindings.

### 10.4 Pricing

- **SFU egress:** 1,000 GB/mo free, then $0.05/GB.
- **TURN:** 1,000 GB/mo free, then $0.05/GB. Free when paired with SFU.
- **RealtimeKit:** per-minute (verify dashboard).
- **smart-turn-v2:** runs on Workers AI — neuron-based pricing.

### 10.5 Office Town relevance — v2

If/when Office Town offers "talk to the wiki" voice agents, Realtime + Pipecat is the path. Not a v1.0 / v1.1 priority — text MCP is the core capability.

## 12. AI Search vs DIY (Vectorize + D1)

The decision Office Town has to make in v1.1/v2. Here's the matrix.

### 12.1 AI Search wins when

- **You want zero pipeline code.** Drop files into R2 → instant search. No chunking config, no embed call, no upsert.
- **Continuous indexing is required.** Files added/modified/deleted should reflect in search within minutes, automatically.
- **You don't want to operate a vector DB.** Cloudflare manages the lifecycle.
- **Hybrid search + similarity caching matter.** Both are built-in.
- **You want an MCP endpoint without writing it.** AI Search exposes itself as MCP.
- **Embeddable UI components.** Drop a search widget into any page.
- **The embedding model choice can stay Cloudflare's default.** You're not picky.

### 12.2 DIY (Vectorize + D1 + custom pipeline) wins when

- **You need control over chunking edge cases.** E.g. don't chunk inside code blocks; treat frontmatter specially; respect heading boundaries.
- **You want non-text content embeddings.** Image embeddings, code embeddings via a specific model.
- **The embedding model needs to change.** AI Search locks it at instance creation.
- **You need fine-grained metadata.** Custom metadata indexes, complex filters, namespace strategies.
- **You're already building the pipeline for other reasons.** E.g. an ingestion Queue that does more than embedding.
- **You need the search API to be exactly your shape.** AI Search's response shape is fixed.
- **Cost matters at very high scale.** DIY scales linearly with usage; AI Search beta is free but production pricing TBA.
- **You don't want lock-in.** DIY lets you swap Vectorize for Pinecone later if needed; AI Search owns the data.

### 12.3 Office Town's current call (2026-05-28)

**v1.0:** DIY. We control the chunking (which matters for Markdown wiki content with code blocks and frontmatter), we want our own metadata shape (`spaceId`, `tags`, `updatedAt`, `authorId`), and AI Search is still in beta.

**v1.1 evaluation gate:** when AI Search is GA, build a benchmark — same corpus, same queries, AI Search vs current DIY. Compare:
- Quality (does AI Search find what users want?)
- Latency (p50/p95)
- Cost (extrapolate AI Search pricing)
- Operational load (does anything still break that we have to fix?)

If AI Search wins on 3 of 4, switch. If DIY wins on quality + cost, stay.

**v2:** likely keep DIY for the wiki itself, possibly add AI Search for **specific user-uploaded content** (e.g. a "this PDF is too big to manually index, just give me search over it" feature).

## 13. MCP Sampling integration

MCP servers can request the host LLM to do work via the **sampling/createMessage** capability. This lets an MCP server ask "summarise this for me" without bundling its own LLM.

### 13.1 The opportunity

Office Town's MCP server can offload work to:
1. **The connected Goose client's host LLM** (whatever the user picked — Anthropic, OpenAI, Workers AI).
2. **Office Town's own Workers AI binding** (if the request shouldn't go via the client).

### 13.2 Sampling pattern — request from MCP server

```typescript
// Inside an MCP tool handler
async function summarizeViaHost(server: McpServer, text: string): Promise<string> {
  const result = await server.createMessage({
    messages: [{
      role: 'user',
      content: { type: 'text', text: `Summarize in 3 bullets:\n\n${text}` },
    }],
    maxTokens: 500,
    modelPreferences: {
      // hints for the client about which model to use
      hints: [{ name: 'claude-haiku-4-5' }],
      costPriority: 0.5,
      speedPriority: 0.7,
      intelligencePriority: 0.3,
    },
  })
  // result.content[0].text is the LLM response
  return result.content[0].type === 'text' ? result.content[0].text : ''
}
```

The host (Goose) decides which model handles the sampling — user retains control.

### 13.3 Workers AI as the host LLM via sampling

If Office Town hosts an MCP server that ALSO has a UI that talks to its own LLM, that LLM can be `env.AI`. Then sampling/createMessage from a sub-tool routes to `env.AI.run(...)` — keeping everything on-account, no extra API keys.

### 13.4 Office Town relevance — v1.1

In v1.0, the MCP server doesn't sample — every tool just returns data. v1.1 brings sampling for tools like:
- `summarize-wiki-page` — calls back to the host for an AI summary, no LLM bundled.
- `suggest-tags` — sampling to suggest tags for a freshly-uploaded doc.
- `find-similar-pages` — semantic re-rank of vector results using host LLM judgement.

Pattern: any tool whose value is "the LLM does X on this data" should be a sampling call, not a built-in LLM. Keeps the MCP server thin + lets users keep using their preferred LLM.

### 14.1 Critical v1.0 → v1.1 path

The most-leverage upgrades for Office Town's v1.1, ranked by ROI:

1. **toMarkdown for images (OCR)** — single binding call, unlocks "drop a screenshot, search the text". Tiny effort, massive UX win.
2. **AI Gateway for cache + observability** — flip one parameter on every `env.AI.run()`. Saves money on duplicate embeddings, gives us a dashboard.
3. **Hybrid search (RRF fusion of FTS + Vectorize)** — already half-implemented; ~50 lines to finish. Significant quality win.
4. **MCP sampling for 3 tools** (`summarize`, `suggest-tags`, `rerank`) — keeps LLM out of our server, lets users pay their own way.
5. **AI Search evaluation** — 1-day spike: index the same corpus, run 50 benchmark queries, compare to DIY. Don't switch yet — gather data.

### 14.2 v2 — the bigger architectural moves

1. **Per-user Agents SDK assistants** — `office-town/user-<id>` with state, inbox, scheduled tasks.
2. **AI Search switch** (if v1.1 eval shows clear win).
3. **Voice mode** via Realtime SFU + Pipecat + Workers AI STT/TTS — only if there's actual user demand.
4. **LoRA per fleet** — fine-tune a small model on the user's wiki for tone-matched generation.

### 14.3 What we deliberately don't do

- **Self-host LLMs.** Workers AI is fine for embeddings + Aura/Whisper; for high-stakes reasoning, MCP sampling routes to the user's chosen model.
- **Cloudflare Stream for v1.x.** Not the product's value prop.
- **AI Gateway for streaming.** Per `rules/cloudflare-workers.md` — known bugs, doesn't pay off.
- **Cloudflare RealtimeKit.** If we go voice, SFU + Pipecat — not the high-level kit.
